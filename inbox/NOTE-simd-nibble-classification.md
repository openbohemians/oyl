# Note: classifying bytes against a set with two table lookups

**From:** the C0DATA session (`~/Projects/c0`), 2026-10-05
**For:** whoever is working on yam's scanner
**Status:** information only. Nothing in yam was changed; this file is the
only thing added, and it is untracked.

## Why this note exists

While discussing byte scanning for C0DATA, the question came up whether yam
already uses the "two table lookup" method of classifying bytes, the one
simdjson uses to find structural characters. I read `src/yam_simd.c` and
`src/yam_simd.h` (read-only) to answer it.

**Answer: no, yam does not use it today.** What yam does:

| Function | Set | Method |
|---|---|---|
| `yam_scan_plain_scalar` | `c <= ' '`, `# : , [ ] { }`, `0x7F` | SSE4.2 `PCMPESTRI` with ranges |
| `yam_skip_blanks` | space, tab | two `_mm_cmpeq_epi8` + OR |
| `yam_scan_to_break` | `\n`, `\r` | two `_mm_cmpeq_epi8` + OR |
| `yam_find_any4` | four given bytes | four `_mm_cmpeq_epi8` + OR |

There is no `_mm_shuffle_epi8`, no AVX2 path, and no ARM path: on ARM every
scan runs the scalar fallback.

For the two- and four-member sets the compare-and-OR approach is already
the right one; a lookup would not beat it. The method below is relevant
only to `yam_scan_plain_scalar`, which tests a large set, and to getting a
vector path on ARM.

## The method

Goal: for a block of 16 bytes, produce one bit per byte saying "this byte
is in my set", at a cost that does not grow with the size of the set.

It rests on one instruction, `PSHUFB` (`_mm_shuffle_epi8`, SSSE3) on x86 and
`TBL` (`vqtbl1q_u8`) on ARM, which does sixteen table lookups at once: each
input byte is used as an index into a 16-entry table.

A byte has a high nibble and a low nibble, each a number 0–15, which is
exactly the size of that table. So:

1. Build two 16-entry tables, one indexed by high nibble, one by low.
2. Look every byte up in both.
3. AND the two results. Non-zero means the byte is in the set.

To build the tables, group the set's members by high nibble and give each
group one bit. High nibbles whose members have the same set of low nibbles
can share a bit. The high table says which group a high nibble belongs to;
the low table says which groups a low nibble appears in. It is exact as
long as no more than eight bits are needed.

Bytes `>= 0x80` have high nibbles 8–F, which map to zero in the high table,
so UTF-8 continuation and lead bytes are never members. No special case.

## Worked out for yam's plain-scalar set

Groups:

| Bit | High nibbles | Low nibbles | Members |
|---|---|---|---|
| 0 | 0, 1 | all | `0x00`–`0x1F` |
| 1 | 2 | 0, 3, C | space, `#`, `,` |
| 2 | 3 | A | `:` |
| 3 | 5 | B, D | `[`, `]` |
| 4 | 7 | B, D, F | `{`, `}`, `0x7F` |

Tables (index 0 first):

```c
/* indexed by high nibble */
0x01, 0x01, 0x02, 0x04, 0x00, 0x08, 0x00, 0x10,
0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00

/* indexed by low nibble */
0x03, 0x01, 0x01, 0x03, 0x01, 0x01, 0x01, 0x01,
0x01, 0x01, 0x05, 0x19, 0x03, 0x19, 0x01, 0x11
```

These were generated by a script and checked against the scalar predicate
in `scan_plain_scalar_scalar` for all 256 byte values.

A 16-byte loop using them:

```c
__attribute__((target("ssse3")))
static size_t scan_plain_scalar_ssse3(const char *buf, size_t len) {
    const __m128i hi_tab = _mm_setr_epi8(
        0x01, 0x01, 0x02, 0x04, 0x00, 0x08, 0x00, 0x10,
        0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00);
    const __m128i lo_tab = _mm_setr_epi8(
        0x03, 0x01, 0x01, 0x03, 0x01, 0x01, 0x01, 0x01,
        0x01, 0x01, 0x05, 0x19, 0x03, 0x19, 0x01, 0x11);
    const __m128i low4 = _mm_set1_epi8(0x0f);
    size_t i = 0;
    for (; i + 16 <= len; i += 16) {
        __m128i chunk = _mm_loadu_si128((const __m128i *)(buf + i));
        __m128i lo  = _mm_shuffle_epi8(lo_tab, _mm_and_si128(chunk, low4));
        __m128i hi  = _mm_shuffle_epi8(hi_tab,
                          _mm_and_si128(_mm_srli_epi16(chunk, 4), low4));
        __m128i hit = _mm_and_si128(lo, hi);       /* non-zero = member */
        int miss = _mm_movemask_epi8(
                       _mm_cmpeq_epi8(hit, _mm_setzero_si128()));
        if (miss != 0xFFFF)
            return i + (size_t)__builtin_ctz((unsigned)~miss & 0xFFFF);
    }
    /* scalar tail, as in the existing implementations */
    ...
}
```

I compiled this (with the scalar tail filled in) and compared it against
the scalar scan on 200,000 random buffers of length 0–95, half of them
arbitrary bytes. No mismatch. That is a correctness check only; I did not
benchmark it and did not run yam's own tests against it.

## Things to know before using it

- **`PSHUFB` zeroes the output where the index byte has its top bit set.**
  That is why both indexes are masked with `0x0f` above. There is no
  per-byte shift in SSE, so the high nibble is taken with a 16-bit shift
  and then masked.
- **It needs SSSE3, not SSE4.2.** Any CPU the current dispatch accepts has
  it, so the existing `__builtin_cpu_supports("sse4.2")` check is enough.
- **Measure it.** `PCMPESTRI` is microcoded and often slow, which is the
  usual reason to replace it, but the plain-scalar set is mostly one range
  (`<= ' '`) plus eight bytes, so a single unsigned compare plus a few
  equality compares is a third candidate. `bench/bench_scanner.c` is the
  place to compare all three. I would not assume a winner.
- **AVX2** (`_mm256_shuffle_epi8`) looks up within each 128-bit half
  separately, so the 16-entry tables must be repeated in both halves. Then
  the same code handles 32 bytes per step.
- **ARM NEON** has the same operation as `vqtbl1q_u8`, and there an index
  out of range gives zero, with no top-bit rule. This method is the easy
  route to a vector path on ARM, which yam does not have at present. NEON
  has no `movemask`; the usual substitute is `vshrn_n_u16` to narrow the
  comparison result to a 64-bit value with four bits per byte.
- **The bits can carry classes, not just membership.** With the tables
  above, bit 0 alone already says "control character", and a different
  assignment could separate whitespace from indicators in the same pass.
